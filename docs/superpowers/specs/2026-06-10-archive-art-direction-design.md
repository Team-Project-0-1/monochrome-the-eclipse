# 아카이브 아트 디렉션 — 상용게임급 다이어제틱 UI 전환 (디자인 스펙)

날짜: 2026-06-10
상태: 사용자 승인 대기 → 승인 후 화면별 plan 문서의 상위 기준 문서가 됨

## 0. 이 문서를 읽는 에이전트에게

이 문서는 픽셀 명세가 아니라 **의도와 맥락의 고정 문서**다. 어떤 에이전트가 어느 화면을 작업하든:

1. **§1 디자인 언어**(불변 규칙)와 **§2에서 자기 화면의 의도 3줄**을 읽으면 작업을 시작할 수 있어야 한다.
2. 구체 레이아웃·연출 디테일은 **에이전트의 자유 영역**이다 — 구현 후 캡처 육안 리뷰로 다듬는다.
3. 단, §1의 불변 규칙(재질·타이포·연출 문법·접근성)을 어기는 자유는 없다.

## 1. 문제와 방향

**문제**: 현재 메타 화면들(보상·상점·휴식·이벤트·탐험·메뉴 등)은 "배지 칩 + 대형 타이틀 + 설명 문단 + 반투명 글래스 카드 그리드 + 하단 팁 패널"이라는 웹 대시보드 문법으로 만들어져 있다. 게임이 아니라 정보 페이지처럼 읽힌다. (전투 화면은 예외 — 이미 게임다운 품질로, 이번 작업의 **기준점**이다.)

**방향**: 슬레이 더 스파이어급 상용 게임의 몰입감. 합의된 최우선 재료는 **다이어제틱 레이아웃** — 정보가 패널 속 텍스트가 아니라 게임 세계의 물건으로 존재하는 것.

**세계관 은유 (모든 화면의 공통 무대)**: **"기록 보관자의 책상."**
플레이어는 메뉴를 조작하는 게 아니라, 어두운 책상 위에서 기억의 물증 — 사진, 편지, 필름, 파편 — 을 손으로 다룬다. 게임 테마(일식·기억·감각·메아리)와 자원 명칭(기억 조각·감각 파편·메아리 잔향)이 이 은유에 직접 대응한다.

## 2. 디자인 언어 — 불변 규칙

### 2.1 재질 (Material)

| 요소 | 웹 문법 (제거 대상) | 아카이브 문법 (적용 규칙) |
|---|---|---|
| 화면 배경 | 배경 이미지 + 검정 스크림 + 그라데이션 | **책상 표면 텍스처** + 비네팅. 낮은 조도, 광원은 하나(스탠드 불빛) |
| 패널/카드 | 반투명 글래스 사각형 + 네온 보더 | **인화지(은염 사진)·종이·필름** — 질감 있는 표면, 잘리거나 찢긴 가장자리, 9-slice 프레임 |
| 정보 칩/배지 | 라운드 사각 칩 + uppercase 트래킹 | **잉크 스탬프, 타자 캡션, 연필 주석, 클립/테이프** 중 장면에 맞는 것 |
| 전역 질감 | 없음 | **필름 그레인 미세 오버레이** — 전 화면 통일감의 핵심. reducedMotion 시 정적 프레임 |

### 2.2 색 (Color)

- 베이스: **모노크롬 사진 톤** — 웜 그레이~은빛. 네온 글로우 금지.
- 기능색(노드 타입·자원 구분 등 기존 체계)은 **유지하되 채도를 낮춰 "잉크/스탬프" 느낌으로**. 색이 빛나는 게 아니라 종이에 스며든 것처럼.
- 기존 `docs/superpowers/specs/2026-06-10-exploration-functional-color-hierarchy-design.md`의 기능색 위계 원칙과 충돌하지 않는다 — 표현 재질만 바뀐다.

### 2.3 타이포그래피 (Typography)

- 디스플레이(타이틀·도장·라벨): `font-orbitron`(SF/테크 느낌) 사용 중지. **활판·타자기 계열 명조 1종**으로 교체 (Phase 0에서 라이선스 확인 후 woff2 서브셋 번들).
- 본문: 가독성 우선 — 현 본문 서체 유지.
- 대형 헤드라인으로 화면을 설명하지 않는다. 화면의 정체는 장면이 말하고, 텍스트는 물건 위의 기록(캡션·스탬프)으로만 존재한다.

### 2.4 연출 문법 (Motion Grammar)

- **물리 문법**: 호버 = 물건이 살짝 들리고 기울며 은빛 반사. 선택/확정 = 인화 플래시 + 도장. 등장 = 책상 위로 떨어지거나 놓임. 퇴장 = 아카이브에 철해짐.
- CSS `translate + glow` 호버, 의미 없는 pulse 애니메이션 금지.
- **reducedMotion**: 모든 물리 연출(낙하·기울임·플래시) 생략, 크로스페이드만. framer-motion은 CSS 가드가 안 먹으므로 컴포넌트에서 `gameOptions.reducedMotion`을 직접 게이팅(기존 관례).

### 2.5 접근성 (불변)

- 선택 가능한 물건은 전부 실제 `<button>`(또는 동등 role). 물건 전체가 클릭 타깃.
- 포커스 시 호버와 동일한 물리 반응 + 가시 포커스 링.
- 도장·캡션 등 시각 텍스트가 흐릿한 경우 aria-label로 보완. 정보 손실 금지 — 제거하는 건 표현이지 정보가 아니다.

## 3. 전 화면 의도 (화면별 3줄: 만지는 물건 / 제거하는 것 / 건드리지 않는 것)

### 3.1 보상 선택 — 우선순위 1 (버티컬 슬라이스)
- **장면**: 전투 승리 → 셔터 암전 → 책상 위로 떨어진 빛바랜 사진 3장. 선택 = 하나를 보관(아카이브에 철함).
- **만지는 물건**: 선택지 = 인화지 사진(상단 2/3 피사체, 하단 1/3 타자 캡션 = 기존 label + `getRewardChoiceCue`). 스킬/패시브 상세(EffectSummary)는 호버/포커스 시 옆에 끼워지는 메모지.
- **제거**: "보상 선택" 배지, `text-6xl` 타이틀, 설명 문단, 카드 내부 별도 선택 버튼(카드 자체가 버튼), 하단 팁 패널(책상 모서리 메모지로 강등).
- **건드리지 않음**: `claimCombatReward` 로직, 보상 데이터 구조, "현재 상태" 버튼 기능(스타일만 교체), 사운드 훅.

### 3.2 상점 — 우선순위 2
- **장면**: 수집상의 진열대 — 펠트 천 위에 물건들이 종이 가격표를 달고 놓여 있다.
- **만지는 물건**: 상품 = 진열된 물증 + 가격표. 보유 자원 = 책상 위 주머니/동전 더미(숫자는 꼬리표). 구매 비교 = 손에 든 두 물건을 나란히.
- **제거**: 상품 그리드의 대시보드 칩 문법, 상단 리소스 스트립의 "잔액 표시줄" 느낌.
- **건드리지 않음**: 구매 로직·가격 데이터, 모바일 sticky 자원 표시의 *기능*(표현만 교체).

### 3.3 휴식 — 우선순위 2
- **장면**: 암실(현상실) — 붉은 안전등 하나가 켜진 어두운 방.
- **만지는 물건**: 선택지(회복/성장 등) = 행동을 찍은 폴라로이드 2~3장. 회복 수치 = 현상액 속에서 떠오르는 이미지로 결과 표현.
- **제거**: 선택지 버튼의 폼 UI 문법.
- **건드리지 않음**: 휴식 로직(회복 비율 등 밸런스 값).

### 3.4 이벤트 — 우선순위 2
- **장면**: 발견된 기록 — 책상 중앙에 놓인 편지/사진 한 장.
- **만지는 물건**: 시나리오 텍스트 = 기록물 그 자체(편지지·사진 뒷면에 쓰인 글). 선택지 = 여백의 연필 주석. 결과 = 기록 위에 찍히는 도장(성공/실패).
- **제거**: 시나리오 텍스트를 담는 패널-속-패널 구조.
- **건드리지 않음**: 이벤트 데이터·확률 로직, eventPhase 상태 기계.

### 3.5 탐험 — 우선순위 3 (씬-우선 A+B 계획 머지 후 착수)
- **장면**: 네거티브 콘택트 시트 — 필름 인덱스를 들여다보며 다음 프레임을 고른다.
- **만지는 물건**: 노드 카드 = 필름 프레임. 경로 지도(RouteMapOverlay) = 콘택트 시트 위 그리스펜슬 표시. 상단 바(RunTopBar) = 책상 가장자리의 도구들.
- **제거**: (A+B가 이미 사이드 레일·콩알 미니맵을 제거함 — 이 작업은 그 구조 위에 재질만 입힌다.)
- **건드리지 않음**: `2026-06-10-scene-first-summoned-ui.md`가 만든 구조(상단 바·오버레이 토글), 노드 가용성 로직, 기능색 위계.

### 3.6 메인 메뉴 — 우선순위 3
- **장면**: 서고의 책상 전경 — 게임의 첫 인상. 이 화면이 아트 디렉션의 표지다.
- **만지는 물건**: 메뉴 항목 = 책상 위 물건(서류철 = 이어하기, 새 필름 = 새 기록, 캐비닛 = 설정).
- **제거**: 세로 버튼 스택 문법.
- **건드리지 않음**: continueRun/startGame 로직, 세이브 표시 정보.

### 3.7 캐릭터 선택 — 우선순위 3
- **장면**: 인사 기록 파일 — 클립으로 철한 인물 기록 카드(수배 사진풍).
- **만지는 물건**: 캐릭터 카드 = 사진 + 타자 프로필 + 클립/도장. 선택 = 파일을 집어 든다.
- **제거**: 캐릭터 카드의 게임패널 문법.
- **건드리지 않음**: 캐릭터 데이터·선택 로직, e2e가 의존하는 `data-testid`(`character-card-warrior` 등).

### 3.8 기억 제단 — 우선순위 4
- **장면**: 색인 카드 캐비닛/앨범.
- **만지는 물건**: 업그레이드 목록 = 서랍 속 색인 카드. 구매 = 카드에 도장.
- **제거**: 업그레이드 목록의 테이블/리스트 문법.
- **건드리지 않음**: 업그레이드 데이터·비용 로직.

### 3.9 승리 / 게임오버 / 스테이지 클리어 — 우선순위 4
- **장면**: 사건 종결 보고서(승리·클리어) / 빛에 타버린 필름(게임오버).
- **만지는 물건**: 런 통계 = 보고서 양식 위 타자 기록. 재시작/메뉴 = 보고서 하단 결재란.
- **제거**: 통계 카드 그리드 문법.
- **건드리지 않음**: `recordRunEnd` 텔레메트리, 재시작 로직.

### 3.10 전투 — 우선순위 5 (톤 정합만)
- 전투는 품질 기준점이므로 **재설계하지 않는다**. 마지막에 필름 그레인 오버레이 적용과 프레임 톤 정합(색·질감의 위화감 제거)만 수행한다.

## 4. 실행 전략

### Phase 0 — 파운데이션 (모든 후속 작업의 유일한 공유 의존)
1. **토큰**: `tokens.css`에 `--archive-*` 변수 추가(종이·잉크·은빛·책상 색, 그레인 불투명도).
2. **서체**: 활판/타자 계열 명조 1종 선정 — 라이선스 확인 → woff2 한글 서브셋 → 번들.
3. **텍스처 자산 6~8종 AI 생성**: 책상 표면 1, 인화지 9-slice 프레임 2종, 필름 그레인 타일 1, 스탬프/테이프/클립 장식 2~3종. WebP 모노크롬, **합계 ~300KB 목표**(그레이스케일이라 고압축). 미세 효과(비네팅·잉크 번짐·그레인 애니메이션)는 CSS/SVG 절차 생성.
4. **공용 컴포넌트 4종**: `ArchiveSurface`(화면 배경 래퍼), `ArchiveCard`(인화지 프레임), `ArchiveStamp`(도장 라벨), `ArchiveCaption`(타자 캡션).
5. **CSS 충돌 회피**: 전부 신규 `.archive-*` 네임스페이스, 신규 파일 `src/styles/components/components-08-archive.css`(import 체인 마지막). 기존 1,415개 `!important` 캐스케이드와 셀렉터가 겹치지 않으므로 특이성 전쟁 없이 공존. **기존 components-01~07 수정 금지**(화면 전환 시 구 클래스 제거는 각 화면 plan에서).

### Phase 1 — 보상 화면 버티컬 슬라이스 = 검증 게이트
- §3.1 구현. e2e 캡처 + 수동 스크린샷으로 **사용자 육안 승인을 받기 전에는 다른 화면 확산 금지**.
- 실패 판정 시 Phase 0 자산/토큰만 교체 후 재시도(슬라이스 범위 밖 비용 0).

### Phase 2+ — 화면별 확산
- 순서: 상점 → 휴식 → 이벤트 → 탐험(씬-우선 A+B 머지 후) → 메뉴·캐릭터 선택 → 기억 제단·엔딩류 → 전투 톤 정합.
- **화면당 독립 plan 문서 1개**(superpowers writing-plans 규약). plan은 이 스펙의 §1 + 해당 화면 §3.x를 인용하는 것으로 시작한다.
- 화면 간 의존성 없음 → **병렬 에이전트 투입 가능**. 공유 의존은 Phase 0 산출물뿐.

### 공통 검증 (모든 화면 plan에 포함)
- `npm run check` 통과 (dist 예산 — 텍스처 추가분 감시 포함).
- e2e 스모크 통과 + 해당 화면 스크린샷 육안 확인.
- reducedMotion ON 수동 확인(물리 연출 전부 생략되는지).
- e2e가 의존하는 `data-testid` 보존.

## 5. 제약·리스크

- **dist 예산 15MB**: 텍스처 합계 ~300KB 목표라 여유 충분. 단 화면별 추가 자산 생성 시 매 plan에서 `check:dist`로 감시.
- **서체 라이선스**: 무료 상용 가능(OFL 등) 한글 서체로 한정. Phase 0에서 확정 전 어떤 화면 plan도 타이포 작업 금지.
- **AI 텍스처 품질 변동**: Phase 1 게이트가 이 리스크의 방화벽. 게이트 통과 전 확산 금지가 규칙.
- **기존 작업과의 관계**: 씬-우선 A+B(`docs/superpowers/plans/2026-06-10-scene-first-summoned-ui.md`)는 구조 작업, 본 스펙은 표현 작업 — 충돌 없음, 탐험만 순서 의존.
